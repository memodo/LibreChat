## Key Discoveries

1. **Stale-dist root cause** — `packages/api/dist/` is gitignored. `git pull` carries source but not dist. The first SPEC-014 deploy ran vanilla LibreChat code despite our source changes being on disk. Resolved by rebuilding dist on prod via ephemeral `node:22-alpine` container.

2. **`prod-sync.sh` already existed** — it's the canonical tool for this exact case (rsync built dist directories to prod, with a missing-dist guard). The first SPEC-014 deploy command in the spec didn't reference it — a spec gap, now fixed by commit `f51543716`.

3. **Three LibreChat v0.8.5 upstream limitations** (documented fully in `SDD/research/RESEARCH-015-librechat-agent-bridge-byot-mcp.md`):
   - **A.** yaml-sourced MCP servers don't persist `toolFunctions` to the admin DB; `getMCPTools` returns empty at agent runtime.
   - **B.** Admin UI's Add-MCP-Server dialog doesn't support the `{{LIBRECHAT_GRAPH_ACCESS_TOKEN}}` placeholder header pattern (only None / API Key / OAuth auth modes).
   - **C.** UI-source rename doesn't propagate to discovered `toolFunctions` keys (keys retain `_mcp_temp_server_name` suffix).

4. **Softeria 0.110.0 specifics from running it:**
   - Requires Authorization on ALL JSON-RPC calls including `initialize` (drove the `startup: false` + `--no-restart` flag in deploy sequence).
   - Returns HTTP 401 on bare unauthenticated GET (drove the healthcheck regex extension).
   - Advertises MCP protocolVersion `2025-11-25` (the LATEST_PROTOCOL_VERSION from the MCP SDK).
   - Writes file-logs to `${HOME}/.ms-365-mcp-server/logs/` at boot (drove the tmpfs mount under `read_only: true`).

5. **DEBUG_OPENAI=true breaks LibreChat v0.8.5's logger entirely** — diagnostic dead-end. Useful negative result: in v0.8.5, this flag silently disables stdout logging.
