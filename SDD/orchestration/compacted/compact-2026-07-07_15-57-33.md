## Key Discoveries
- **`requiresEphemeralUserConnection()` (`packages/api/src/mcp/utils.ts:191`) gates on
  `{{LIBRECHAT_BODY_*}}` placeholders, NOT `obo`.** So M365 is user-scoped but NOT request-scoped; its
  172 tools ARE persistently cached under `{userId,serverName}`. The prompt's "mcp_all overlay" premise
  was wrong; the real gate was the missing `"tools"` capability.
- **OBO cache `expires_at` inflation bug:** the cache stored a fixed `expires_in`, so `resolveOboToken`
  recomputed an inflated `expires_at` on every cache hit — would have defeated the near-expiry check.
  Fixed by stamping absolute `expires_at` at mint + force-fresh on near-expiry.
- **People Search silently fell back to LOCAL users until 2026-07-04** (Entra Part A+B) + C.5
  (`PermissionsController.js:38 getOboAssertionToken` = `req.user.federatedTokens.access_token`). The old
  "verified 2026-06-11" was inaccurate. Feature gate needs BOTH `USE_ENTRA_ID_FOR_PEOPLE_SEARCH` +
  `OPENID_REUSE_TOKENS` + an openid user (`GraphApiService.entraIdPrincipalFeatureEnabled`).
- **The 6 "failing" `src/mcp` suites are infra-gated integration tests** (`*.integration`/
  `*.cache_integration`), excluded from `test`/`test:ci` via `--testPathIgnorePatterns`; need a real
  Redis cluster. NOT regressions. Real gated suite = **46 suites / 1178 pass**.
- **Org-mode vs read-only are different axes.** SharePoint/Teams are hidden by org-mode (off), not
  read-only. Sidecar levers: `MS365_MCP_ORG_MODE` + `MS365_MCP_ALLOWED_SCOPES` (scope-driven tool
  surface; matcher collapses scope hierarchy). SharePoint read needs only already-granted scopes; Teams
  needs 10 new admin-consented delegated scopes.
