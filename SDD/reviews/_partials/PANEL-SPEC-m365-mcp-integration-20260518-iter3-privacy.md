#### Privacy Findings (Iter 3)

- **L** Correlation-ID composition is PII-safe but verify it's not user-identifying across systems
  - Evidence: REQ-023 specifies `client-request-id = ${conversationId}:${messageId}:${toolCallId}` — three opaque internal IDs, no email/UPN/oid embedded. SEC-004 separately keys audit reconstruction on Entra `oid` (the JWT claim, not the correlation-ID). Verification §7 confirms the same ID appears in LibreChat audit logs, sidecar logs, and Graph activity logs.
  - Risk: Low. The correlation-ID format is non-PII by construction (no email/UPN/oid). It does, however, create a *linkability vector* across three log surfaces (LibreChat + sidecar + Graph activity log) — which is the intent (audit reconstruction per SEC-004), but it means anyone with access to all three logs can re-identify the user via Graph's side. Mitigated because (a) Graph activity log access is gated by Entra admin role, (b) SEC-007/SEC-004 negative assertions block payload leakage on the LibreChat and sidecar sides, (c) conversationId/messageId/toolCallId are not user-derived.
  - Resolution: Acceptable as drafted. Optional hardening (not blocking): note in REQ-023 that the correlation-ID MUST NOT be derived from or contain the user's email, UPN, oid, or display name — purely from internal conversation/message/toolCall identifiers. This codifies the iter3 anti-pattern #11 explicitly.

- **L** REQ-029 retention timer existence is a known unknown gated by governance, not by spec
  - Evidence: REQ-029 states "conversations older than 12 months are purged unless pinned" and that "the retention timer is enforced by the existing LibreChat retention mechanism (location: TBD by implementation PR; if absent, see Open Decision OD-6)." OD-6 makes the indefinite-retention residual a DPO-equivalent written acceptance and a production-rollout blocker.
  - Risk: Low (residual). If the LibreChat retention mechanism turns out not to exist in this fork, the technical control is absent and the governance path (OD-6 DPO acceptance in writing) becomes the only safeguard. Acceptable under iter3 rubric: "out of scope, tracked at OD-6" is a valid resolution and OD-6 is named as blocking for production rollout.
  - Resolution: No change required. Implementation PR will confirm presence/absence of the timer (a 30-minute grep of `api/server/services` and `packages/data-schemas` for conversation TTL / purge logic) and either land it or escalate via OD-6.
